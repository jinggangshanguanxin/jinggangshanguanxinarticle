# 文章加载慢修复计划

## 根因
1. **主因**：`sync.py` 的 mammoth 转换没覆盖默认图片处理 → 每张图片 base64 内嵌进文章 HTML。中位文章 1.26MB、最大 17MB，其中 98%+ 是图片字节。整块下载完才能渲染。
2. **次因**：`app.js` 启动时急加载 4.5MB 的 `search-index.json`，与首次文章点击抢带宽。
3. 次要：`index.html` head 同步加载 markdown-it / highlight.js / mermaid（~1MB），拖慢首屏。

## 修复（3 个文件，最小改动）

### 1. `scripts/sync.py` — 图片外置（核心）
- 给 `mammoth.convert_to_html` 加 `convert_image` 处理器：读取图片字节 → 写入 `reader/docs/img/<文章名>/<md5前12位>.<扩展名>` → HTML 里输出 `<img src="docs/img/...">`（相对路径，与现有 `fetch('index.json')` 同模式，根域/子路径部署都兼容）
- 同内容图片按 md5 命名自然去重；`post_process` 时给 `<img` 注入 `loading="lazy"`
- 清理逻辑补一条：删除没有对应文章的孤儿 `docs/img/` 子目录
- 效果：文章 HTML 从 1.26MB 中位降到几十 KB（纯文本），首屏秒开；图片变普通请求，lazy 并行加载，浏览器可缓存

### 2. `reader/app.js` — 搜索索引懒加载
- `loadSearchIndex()` 改为首次聚焦搜索框时才触发（一次性），启动时不再下载 4.5MB

### 3. `reader/index.html` — head 脚本 defer
- markdown-it / highlight.js / mermaid 三个 `<script>` 加 `defer`，不阻塞首屏

## 验证
- 本机无 Python，靠 CI 构建：推送后跟踪 Actions 至成功
- 线上抽查：之前 17MB 的《实事求是…批判》HTML 应降到 <100KB；其图片 URL 返回 200；文章页能打开、侧边栏/搜索正常
- 注意：`docs/img/` 只存在于 CI 构建产物（`reader/docs/` 已 gitignore 不入库），仓库体积不变；Pages 站点总体积从 ~1.14GB 降到 ~840MB（base64 → 二进制）

## 不做（YAGNI）
- Cache Storage 持久缓存、分块渲染、搜索索引分片——图片外置后 HTML 只有几十 KB，这些复杂度不值得
- Cloudflare 橙云加速：你之前已了解利弊，需要时自己切换即可
